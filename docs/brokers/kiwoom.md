## 주소·인증
- 주소: 실전 `https://api.kiwoom.com`, 모의 `https://mockapi.kiwoom.com`. 모든 TR은 `POST` + JSON. 국내 계좌 TR은 `/api/dostk/acnt` [명세]
- 헤더: `api-id`(TR 코드), `authorization: Bearer …`. 연속 조회는 응답 헤더 `cont-yn=Y`·`next-key`를 다음 요청 헤더에 그대로 넣는다 [명세][FAQ#23]
- 앱키 발급 전에 허용 IP를 등록해야 한다 (최대 10개). 그 밖의 IP에서는 인증이 안 된다 [이용안내]
- 집 공인 IP가 바뀐다. 바뀌면 사람이 포털에서 IP를 다시 등록한다 (2026-10-07 결정). 그동안 키움 조회는 실패하고, 통합 잔고는 `failedBrokers`로 알린다
- 토큰: au10001 `POST /oauth2/token`, 본문 `grant_type`·`appkey`·`secretkey`. 응답 `token`, `expires_dt`(예시 `"20241107083713"`, 14자리, 시간대 명시 없음). 유효 24시간 [명세][이용안내]
  - 발급 후 6시간 안에 다시 요청하면 같은 토큰을 준다. 6시간 뒤 요청하면 새 토큰을 주고 이전 토큰은 폐기 [FAQ#25]
- 명세의 au10001·ka00001 응답 예시는 쉼표가 빠져 JSON이 아니다. 녹화에는 쉼표를 넣었다
- 실전과 모의투자의 앱키가 따로다. 모의투자는 따로 신청한다 [이용안내]
- 실전 도메인에 3개월 접속하지 않으면 서비스가 해지된다 (모의만 쓴 것도 미접속) [FAQ#19]
- 매일 접속 끊김: 월~토 07:50~07:55, 일 05:00~05:15 (REST 안 됨, 웹소켓도 끊김) [FAQ#42]
- 호출 한도: TR당 토큰별 초당 5건, 모의는 초당 1건 [FAQ#41]

## 계좌
- 요청에 계좌번호 필드가 없다. ka00001은 "현재 토큰의 계좌번호를 조회" → `acctNo` 하나(10자리, 뒤 2자리는 키움 분류값). 앱키 파일 이름도 `계좌번호_appkey.txt` → 앱키(토큰) 하나에 계좌 하나로 본다 [명세][이용안내]
- 앱에 보이는 계좌번호는 `acctNo` 앞 8자리다 (뒤 2자리는 분류값, 10/15 dryrun에서 앱과 비교). 화면 끝 4자리는 앞 8자리의 끝 4자리
- 계좌번호로 일반·ISA를 가를 수 없다: `acctNo` 뒤 2자리가 "계좌를 분류하기 위한 값"이라고만 적혀 있고 값 표가 없다. 명세 전체에 ISA 언급이 없다 (2026-10-15 확인). 어느 계좌인지는 앱키를 발급한 계좌로 정해진다
- 실전·모의 각각 계좌를 20개까지 추가 등록할 수 있다. 계좌(위탁/ISA 등)와 HTS ID 연결 필요 [이용안내]
- ISA: 등록 가능한 계좌 종류에 "중개형ISA"가 있다 [FAQ#24]. 포털 '계좌 등록하기'에 일반 계좌와 ISA 계좌 둘 다 등록되어 있다 (2026-10-07, 사람이 확인)
  - 잔고·보유 조회가 실제로 ISA에서 되는지는 2단계 dryrun 첫 조회(사람이 실행)로 확인한다

## 예수금·보유
- 예수금: kt00001 (`qry_tp` 3 추정·2 일반) → `entr`(예수금), `d2_entra`(D+2 추정예수금), `ord_alow_amt`(주문가능금액) 등 [명세]
- 보유: kt00018 (`qry_tp` 1 합산·2 개별, `dmst_stex_tp` KRX·NXT) → 목록 `acnt_evlt_remn_indv_tot`: `stk_cd`(접두어 1자리 + 6자리, A 주식·J ELW·Q ETN), `stk_nm`, `rmnd_qty`, `cur_prc`, `evlt_amt` [명세]
  - 값은 앞을 0으로 채운 부호 포함 숫자 문자열 (`"000000000177000"`, `"-00000000196888"`). 자릿수는 필드마다 다르다 (`cur_prc` 12자리, `evlt_amt` 15자리)
  - 앱 "평가금액"은 `evlt_amt`(현재가×수량)에서 `sum_cmsn`(예상 매입·매도 수수료 합계)과 `tax`를 뺀 값이다. 앱 "총손익" = `evltv_prft` = `evlt_amt` − `pur_amt` − `sum_cmsn` (10/15 dryrun)
  - 앱 "예수금" = kt00001 `entr` (10/15 dryrun)
  - 명세 예시에 같은 종목이 두 줄로 나온다. 두 줄 모두 `crd_tp` "00"(신용 아님)이고 현재가가 서로 달라, 신용 구분 때문이라는 추정은 맞지 않는다. 실제로 여러 줄이 오는지는 dryrun으로 본다

## 오류
- 본문 `return_code`(0 정상)·`return_msg` [명세]. 업무 오류도 HTTP 200으로 온다는 말은 공식 SDK 주석에만 있다 (명세 원문 아님). 명세에 오류 응답 예시는 없다 → 녹화의 오류 파일은 정상 응답 모양에 오류표 코드·문구를 넣어 만들었다
  - 8005 토큰 무효, 8010 토큰 발급 IP ≠ 요청 IP, 8001·8002 앱키·시크릿 실패, 1700·1701·1702 호출 한도 초과, 8030·8031 실전/모의 혼용 [명세 오류코드 표]

## 모의투자
- 모의투자는 실제 계좌와 별개인 가상 계좌다 (상시모의투자, 국내주식·미국주식만) [모의]
- 모의투자는 NXT를 지원하지 않는다. 조회도 KRX만 [모의][FAQ#27]
- 모의투자에 ISA가 있는지는 문서에 없다 → 없다고 본다. 2단계는 모의투자를 쓰지 않고 실계좌로 확인한다 (조회만이라 위험 없음, 2단계 계획서 결정 2026-10-15)

## 실시간
- 웹소켓 `0B`(체결)로 받을 수 있다 [명세]. 만들지 않는다: 국내 체결은 토스 웹소켓이 이미 주고, 키움은 토큰 하나에 웹소켓 하나라 연결을 늘리지 않는다 (2단계 계획서 결정)
